# Circle

All protected effects authenticate Sessioning.use from the host cookie before reading user data or calling a provider. Bodies cannot select owner, original, referenceDate, corpus, provider credentials or arbitrary indexing sources. Concepts remain independent; composition coordinates them. Six existing static instances and type bindings remain.

Provider wiring is infrastructure: [main.ts](../../src/main.ts) configures an OpenAI adapter from server environment variables, and [assembly.ts](../../src/assembly.ts) injects its `BrainProvider` interface into Graphing and its `Transcriber` interface into Remembering. The shared [adapter](../../src/providers/README.md) is not registered as a concept and introduces no actions, state, endpoint or cross-concept calls. Without a configured key, provider-dependent actions fail explicitly; startup and ordinary stored-data reads remain available. Tests can inject fake providers without contacting OpenAI.

The [owned original](view:Circle.OwnedMemory) reads Remembering._record under owner/memory. Missing, foreign or removed records produce no row. It exposes current content, immutable original, revision and referenceDate. The [saved encounters](former:Circle.SavedMemories) preserves Remembering._list order and joins this owned record with Graphing._card for its exact content/referenceDate and explicit current revision from the owned record. Rows include memory/content/original/revision/referenceDate/card, with nullable card on processing failure. Twenty rows plus lookahead retain paging. List is read-only and never invokes a model.

Recent people retains displayed rows when a page read fails. Retry repeats that failed operation's cursor and append-or-replace intent: a failed Load more appends its successful retry to the existing rows in order, deduplicating encounter identities rather than names; a failed initial load or refresh retries its own replacement operation. A pending request disables duplicate Retry/Load more actions. Account clearing, unauthorized responses and removal invalidation discard failed retry state, and stale replies cannot restore previous-account or removed rows. A successful initial, foreground, save, edit or removal refresh restarts the displayed list from the newest encounters; this is a list-position reset, not stored note loss.

The existing missing/removed-cursor response is an empty page, indistinguishable from reaching the end with this endpoint shape. Recent people refreshes from the newest page on sign-in, returning to the tab, and after saving, editing or removing an encounter. A successful refresh lets the user page forward again with Load more to reach older encounters after another tab removes an anchor. A failed refresh retains visible rows and Retry repeats that refresh; only a successful replacement changes the displayed list. There is no separate Reload from start control. Deleted-cursor recovery uses these existing refresh paths or a browser reload, without automatic request loops or preserving a removed cursor's old position.

When the authenticated saved list has loaded successfully with no encounters and Find is selected, the empty state offers a visible, keyboard-operable Remember your first encounter action and a short synthetic example of a useful encounter note. Activating it deliberately switches to Remember through the existing mode-change behavior and focuses the visible note-entry control; it does not seed an encounter or save automatically. Preserve existing text, form and search drafts and the chosen input mode when switching. Loading and failure states retain their own feedback rather than claiming the account is empty.

The [list endpoint](reaction:Circle.ListMemories) authenticates and accepts after. The [remember endpoint](reaction:Circle.Remember) accepts content/submission and optional timeZone (default America/New_York), authenticates and saves exact content with engine time. Timezone must be an IANA timezone; neither timestamp nor referenceDate is caller-authored. Remembering.inspect then supplies content/referenceDate/revision to Graphing.ingest, or refuses MEMORY_NOT_FOUND when the saved record disappeared; success waits for organization. A retry of the same token/content reuses the original and its original reference date. A conflicting/removed token refuses SUBMISSION_CONFLICT. Provider failure keeps saved text visible and permits deliberate retry. No compensating deletion, automatic model retry or local inference fallback.

The [transcription endpoint](reaction:Circle.Transcribe) authenticates audio/mediaType before Remembering.transcribe. Audio is ephemeral, canonical bounded base64 (4 MiB/two-minute capture); unsupported/malformed audio refuses INVALID_AUDIO. Result text is editable and never auto-saved. Text, Voice and Form are equal entry choices. Changing mode cancels recording/pending transcription and preserves drafts. Account changes/unmount invalidate late responses and stop microphone tracks.

The [prepare edit endpoint](reaction:Circle.PrepareEdit) authenticates memory, reads its owned record, explicitly organizes it at the existing revision if needed, then calls Remembering.inspect again using fresh bindings and reads the matching card. A removed record refuses MEMORY_NOT_FOUND; a concurrently edited record can return its fresh content/revision/referenceDate with a null card. A successful preparation reply with a null card opens the editor from that reply's fresh current content, revision and referenceDate using conservative source grouping, never an older local row. Missing/removed/foreign memory refuses MEMORY_NOT_FOUND before provider work. This supplies the current owned content, its existing referenceDate and a matching or null card for the existing form-only editor. No edit occurs on open/cancel. The [edit endpoint](reaction:Circle.Edit) accepts memory/content/submission/revision plus optional timeZone, authenticates and calls Remembering.edit, then calls Remembering.inspect for the resulting current record and ingests it; disappearance refuses MEMORY_NOT_FOUND instead of dropping a guarded response. Timezone still receives the existing validation and America/New_York omission default, but an edit preserves Remembering's effective source referenceDate rather than reanchoring retained wording to that edit's day or timezone. Same-token unchanged retries acknowledge an already applied edit even if the old revision is stale; reused-token changed content and genuinely stale revisions refuse EDIT_CONFLICT. Current content is the user-reviewed form; first original is preserved. Success waits for reorganization. Processing failure preserves the edit and permits same-token retry. Deletion cannot be undone by an edit or delayed extraction.

Organization failure must not prevent a user from correcting an already saved source. Only when preparation has a generic processing or network failure may the editor use the full last-loaded authenticated Recent people row for that memory as a recovery snapshot. Its current content, revision and referenceDate remain the authority; never substitute its immutable first original, a display summary or a guessed name. Show a visible warning that the editor uses the last-loaded encounter and that it may have changed since loading. This fallback supplies no invented matching card or model output: raw source without usable evidence follows the existing conservative whole-source grouping, overflow and source-day review rules, while guided content keeps its authored fields. Saving still uses the snapshot's expected revision and the existing edit submission-token rules, so an intervening correction conflicts instead of being overwritten.

Do not use this snapshot fallback after unauthorized, not-found or conflict preparation responses; retain their sign-in, removed-encounter or reload guidance. Without a matching local row, retain an actionable preparation error and retry path. Account changes and request-scope invalidation discard the pending preparation and snapshot eligibility, so late replies cannot reopen a previous account's editor. Backend preparation still attempts owned organization and may fail; this client recovery adds no endpoint, input, provider fallback or relaxed evidence limit.

Edit preparation reads current content, never the immutable first original or a display summary, as its source of authored values. A recognized guided memo supplies every Person/When/Does/Discussed/Contact/Notes value directly, including intentionally empty values and absent optional Contact/Notes as empty. Card names, shorter role summaries, inferred facts and context do not refill or overwrite those values. Preserve multiline values under the existing readable-memo serialization rules. Only the existing guided When/date-format adaptation below applies to these authored fields; opening, cancelling and unchanged saving never otherwise replace their detail with card wording. Ordinary guided preparation and saving do not scan or reinterpret Does/Discussed/Contact/Notes for relative-date words, even when a later card quotes the literal name only in Person. Remembering now preserves the encounter's effective source anchor across edits, so older guided relative wording retains its prior calendar meaning without rewriting the authored prose.

The complete guided memo grammar recognizes the required Person, When, Does and Discussed fields in that order, with optional Contact and Notes afterward and the existing indented continuation rules, even when Person is empty. Recognition is independent of whether the values are meaningful. A saved encounter may keep or clear an unknown/ambiguous name during editing; Person is optional in the edit dialog, while the creation Form deliberately still requires a name. The application boundary and edit save validation reject a recognized memo whose field values are all empty or whitespace, rather than counting its labels as note content; new guided When values still receive strict calendar validation even when Person is empty. Any nonblank authored field can supply meaningful encounter content. An existing card with null name is displayed as Unnamed encounter without a heuristic fallback choosing an uncertain alternative; a recognized memo with empty Person likewise uses that label and still displays its recorded details when no card is available. Older unorganized raw notes retain their existing display fallback.

The edit dialog can represent complete existing values without the creation Form's smaller per-field name/activity/discussion/contact/notes caps; the optional Date control retains its standardized date restriction. Existing multiline Person and Contact values use stable multiline edit controls, rather than single-line controls that normalize away line breaks; deleting their last newline must not replace the focused control mid-edit. Creation Form controls retain their deliberate existing restrictions. The saved serialized memo still has the existing total 20,000-character limit, including labels, separators and continuation indentation. Opening a long raw conversion retains every source character visibly. If its readable-form overhead already exceeds the limit, show a specific warning before the current attempt can send an edit request and state how far the form exceeds the limit; keep the complete draft visible without claiming that an earlier save or edit was rolled back. Update this feedback as fields change; a fitting edit may save, while an oversized edit sends no edit request. Do not truncate fields, remove source detail automatically, hide it elsewhere or discard the draft after any refusal. Invalid date input must not make size feedback throw or make the editor disappear.

Every edit dialog explains the fixed source-day rule before saving. With a valid referenceDate, show the actual saved reference day and explain that relative words such as today/yesterday refer to that encounter day, not the current edit day; use an explicit date to describe a different day. With an empty or invalid anchor, state that a source day is unavailable and relative wording cannot establish a reliable date; advise an explicit date for new details. This is guidance about the saved text's interpretation, not permission to fabricate an anchor. Newly typed relative wording in ordinary guided fields uses the same fixed anchor; the raw-conversion review below remains stricter and requires unresolved/new supported wording to be corrected explicitly. This policy preserves unchanged legacy text and literal names without a durable frontend evidence cache, provider change, new endpoint or caller-authored date metadata.

For current raw text or voice text, use exact card source quotes to allocate whole source lines, rather than subtracting paraphrased fact values. A quote crossing lines joins those lines into one group. A group containing activity evidence goes wholly into Does; otherwise discussion evidence assigns it to Discussed, contact evidence to Contact, and remaining source groups go to Notes, in original source order within each field. Activity takes priority when a group supports several fields: retain the complete group once in Does, including any reminder or other detail sharing it. The form includes a visible explanation that details grouped in one field are edited together; this covers all shared groups, including discussion/contact and cross-line groups, rather than only activity groups. Do not also copy that group's source text or derivative activity into another field. Exact name and precise stated-date adaptation may still populate Person and When. If the card has no role/activity fact, or activity evidence has no exact source match or cannot be allocated without ambiguity, conservatively put the whole current raw text once in Does and show the same grouping explanation, leaving Discussed/Contact/Notes empty rather than silently splitting or losing it. This is source allocation, not semantic understanding: separately written paraphrases with no exact evidence may require the user to review and correct the visibly retained text too; no arbitrary semantic deduplication is promised.

Only a currently open raw-to-form conversion carries source-aware date-review context: its existing prepare-edit referenceDate and the exact supplied name/source evidence needed to identify retained literal-name occurrences. Match quotes and allocate groups against unchanged source first. An unambiguously evidenced literal name such as Today or Yesterday stays literal in Person and in every retained source group containing that evidenced occurrence. Protect the specific name span, not its entire quote/group or every other occurrence of the same word. If the supplied evidence cannot distinguish a literal name occurrence from date wording, retain the visible draft and require explicit correction rather than silently choosing either meaning. During source-aware save review, an exemption remains valid only while that evidence still unambiguously identifies the retained name in the edited field; do not invent a broader name exemption after a change.

Then, before presenting a raw conversion, resolve actual retained supported whole-word today/yesterday references outside the protected name spans against the valid source anchor and replace them visibly with absolute MM/DD/YYYY dates. Nearby genuine relative wording still receives this handling. Never derive a missing anchor from the current clock or parse other natural-language dates. If an actual reference lacks an anchor or cannot be made stable, keep it and the draft visible, explain the issue, and require an explicit date or removal before saving. The same source-aware review gates remaining or newly entered supported relative wording in this raw-conversion draft, with no edit request until resolved; evidenced literal names alone never trigger that gate, including when the anchor is missing. Keep this evidence only in the open editor and discard it when that editor ends; no session cache, durable metadata or reconstruction from a later card is required. After conversion saves, current content is guided: subsequent preparation and saving use its six authored fields under the ordinary guided rules above. Genuine raw relative wording was already made absolute or explicitly corrected. Same-token processing retries reuse the exact prepared content and token rather than regenerating dates or evidence.

Save serializes only the six visible, reviewed fields with the validation and formatting above; it never appends hidden source, regenerates residuals from first original, or restores a cleared field. Source allocated to Does is absent from residual Notes, so replacing that grouped activity does not leave an automatic preservation copy of the old activity in current searchable content. After conversion the saved memo is guided content, so a second edit reads its current fields directly and does not accumulate residuals. Useful omitted reminders remain in their visible source group or Notes until the user changes them. Existing revision, submission identity, processing acknowledgement and retry behavior remain. Every validation refusal keeps the complete editable draft visible; never truncate grouped text or retain a hidden preservation copy to satisfy a limit. No inferred card summary becomes an authored assertion during preparation: retain the exact current source group's hedging, negation and attribution, rather than copying the inferred value. Reorganization still follows Graphing's existing uncertainty instructions and evidence validation, and displays returned inferred facts as uncertain; source fidelity does not guarantee a model will interpret every note correctly. This editing policy adds no backend state, provider request or endpoint.

The [seek endpoint](reaction:Circle.Seek) authenticates, saves the need and passes only Remembering._corpus for owner into Graphing.recall. Corpus contains current content/referenceDate/revision. Missing/outdated owned organization is repaired only on explicit search/prepare edit/save. Graphing refuses MEMORY_LIMIT before extraction or organization changes when the complete supplied corpus exceeds 256 encounters or 256 KiB of serialized input, or is invalid. The application exposes this refusal as CONFLICT for search capacity, distinct from INVALID_REQUEST for invalid submitted input. Capacity guidance directs the user to review saved encounters and shorten or remove unneeded notes; changing the search description does not repair an oversized corpus. Preserve the search description and saved notes rather than truncating, automatically deleting or searching an incomplete subset. Seeking may already have saved this need before Graphing refuses; no whole-route rollback is implied.

Late structured-card overflow beyond 256 KiB remains an ordinary opaque processing fault: completed organization is retained and selection does not run. Provider failures and MemoryChanged likewise remain ordinary faults rather than no-effect domain refusals. Generic processing guidance permits manual retry, says that the need or organization may already have persisted, and avoids claiming that no state changed or exposing private provider details. Repeated failure may require reviewing long saved notes or trying again after service recovery; the public opaque fault does not identify which cause occurred.

Cold organization processes the complete supplied corpus sequentially. Multiple provider calls, each with the existing 45-second adapter timeout, can exceed the existing 120-second caller deadline even for a corpus within its count and byte bounds. Expiry ends the caller's wait, not accepted server work, and does not cancel or roll back an admitted action. Manual retry may reuse organization and a validated selection completed by that work; each repeated search still creates another Seeking need identity. No automatic retry, deadline-completion guarantee or cancellation guarantee is added. Provider requests use store:false, strict schema, no conversation state and no account credentials. A stronger model may paraphrase or make marked uncertain inferences; actual IDs, source quotes and ownership remain validated. Same query/corpus/provider configuration reuses its stored selection.

The [need results](former:Circle.NeedResults) reads an owned need and owned recall matches, then joins the current OwnedMemory and Graphing._card again with the explicit current owned revision for exact content/referenceDate equality with the selected card. Edited, withdrawn, missing, unreadable or stale sources are omitted even during processing. Return real source IDs/card and exact original/current notes; no model-authored database records or cross-user context. Empty matches remain an empty suggestions list. If the need itself disappears, required result formation faults promptly with opaque INTERNAL_ERROR rather than silently dropping a response. Selection order is Graphing._matches stored relevance order; the saved list order is capturedAt descending then identity ascending, including its paging cursor. These two intentional source-order choices are covered by former tests. Edit invalidates displayed stale suggestions and pending list replies.

The [forget endpoint](reaction:Circle.Forget) authenticates memory, erases Remembering original/current content first and withdraws Graphing evidence/caches next, acknowledging after both. Original/graph markers block stale save/edit/ingest resurrection. The final owned join hides old evidence in the false interval; failed cleanup is manually retryable with the same identity. Missing/foreign removal is MEMORY_NOT_FOUND, repeated owned cleanup succeeds.

Contact rows remain plain white with name, edit button and red basket. Empty values and Not recorded placeholders are omitted. Expanded cards show useful details; inferred details are visibly uncertain. Recent people includes concise guidance that AI-organized summaries can be mistaken and should be checked against the encounter's current text; the preserved first-saved note is historical reference when an encounter has changed, not proof of a changed summary. Personal notes are a separately labeled nested disclosure, collapsed even when the card opens; heading uses the same 14px size as note text. When the first original differs from current content, this disclosure explains that it shows the first saved wording kept for reference and that editing changes the current encounter rather than this copy. Keep the complete original visible inside the disclosure and do not replace it with a summary. Editing uses an accessible form dialog with Person/When/Does/Discussed/Contact/Notes fields prepared under the current-source authority and grouping rules above, and explicit Save changes/Cancel. No changes on cancel; conflicting edits ask to reopen rather than overwrite. Removal confirmation stays Cancel-focused, named and keyboard accessible; duplicate confirmation clicks send at most one frontend request per opened dialog. This does not promise exactly-once execution across concepts or deliberate cleanup retries.

Remember has equal Text / Voice / Form controls with visible words, icons, accessible names and aria-pressed state, a centered Save, current fonts and hover-only artwork. Form does not require a date; structured fields become readable current content. Text/voice drafts persist across mode switches; editing has a separate draft. The signed-in workspace reserves less decorative space around the composer so Recent people and the first-encounter guidance appear closer to the active task; forms still grow with their content. The sign-in composition, Urbanist/Handlee, warm palette, hover-only artwork and existing control/row character remain. Layout adapts to narrow mobile screens, wraps complete long and Unicode labels/details, uses comfortably sized buttons and scrollable dialogs without horizontal overflow. Keyboard and touch workflows do not depend on hovering the artwork, and reduced-motion preference keeps it still. Pending save/search/edit/removal/transcription guards prevent double submission. Errors honestly preserve saved data and draft tokens. Sensitive content, audio, originals, summaries, fields, and credentials remain redacted from traces.

Search shows a visible polite role=status “Finding connections…” while pending, a found-count or explicit empty result on success, and role=alert on failure. Modal dialogs constrain both dimensions to their containing viewport, scroll vertically, loop Tab/Shift+Tab through enabled controls and support Escape/Cancel. Editing initially focuses Person, returns focus to its initiating edit control when present or Recent people after refresh; confirmed removal focuses Recent people. See [verification and advisory audit](../../../design-docs/verification.md) for measured checks and limitations.

Deferred from P1: recommendations/exclusions, active/saved-search management and reminders, automatic rediscovery, useful/dismissed history (Connecting), cross-note fact transfer and identity merging. Editing and confirmed removal are implemented.

New and edited Form dates are optional and use exactly `MM/DD/YYYY`, with zero-padded month/day and calendar validation (including leap years). The shared serializer, save/edit UI and endpoint input validators reject malformed or impossible guided dates. Free text/voice originals remain exact; Graphing resolves supported dates to ISO `YYYY-MM-DD` for search, and the UI formats date facts as `MM/DD/YYYY`. Edit preparation converts a current guided ISO date to the form format; an intentionally empty guided When stays empty. A nonempty older guided date/context that cannot be represented as a precise date is preserved once in Notes, alongside its current authored Notes, and a precise stated card date may supply When. Raw conversion may likewise use a precise stated card date in the form format while retaining unrepresentable date/context in its visible source group. No card context is otherwise appended to an authoritative guided Notes value. Existing stored originals are never rewritten by reads. `capturedAt` is a database DateTime supplied by engine time, never a caller-authored date string; it remains the initial save instant across edits.
